# TG Chat Client 第一版开发计划

## 目标与已确认需求

个人使用的 Windows 10/11 x64 便携聊天工具，围绕五个账号验证。使用期间账号保持连接，手动切换；最小化或托盘隐藏连续满 5 分钟自动断开，恢复窗口自动重连。各自记住目标群、草稿和引用；主要在同一群聊天，也可切换其他已加入的群。

共用用户维护的短句库，支持添加、编辑、删除与排序。短句插入输入框，可继续编辑后手动发送。支持引用回复，收到的媒体只显示类型占位及附带文字；只发送文字。快捷键仅在窗口前台生效。

所有账号共用 SOCKS5/HTTP 代理，支持认证。手机号、验证码及必要时的两步验证密码登录。按账号、群、北京时间日期保存工具发送成功条数，不等同于群内认可条数。

不实现入群、媒体发送、自动发言、自动切账号、抽奖发现、自动参加、云同步和自动更新。

## 技术基线

- Python 3.12、PySide6 Qt Widgets、Telethon 1.x、python-socks、SQLite。
- Qt 主线程操作界面；后台线程运行长期 asyncio 循环，维护每个账号的独立连接。
- `ServiceBridge` 负责跨线程传递；`ServiceRuntime` 负责操作准入、限流、发送记账；真实与模拟服务使用相同操作接口。
- 操作包括 `start`、`reconnect`、`request_code`、`sign_in`、`cancel_login`、`logout`、`remove_account`、`groups`、`history`、`send`；`set_foreground` 传递主窗口是否显示且未最小化，不依赖窗口焦点。
- 发送使用不可变 `SendRequest`，固定请求 ID、账号、群、文本与引用。事件分为 `status`、`message`、`result`、`error`、`connection_state`，请求结果携带原操作和标识；连接事件报告暂停、断开、恢复与恢复失败。
- 同一账号和群允许多条手动提交的发送同时等待回执，按请求 ID 独立跟踪。其他账号可继续操作；任何发送未完成时拒绝修改连接、登录、退出登录及移除账号。
- 请求失败不排队、不自动重发；网络错误、超时、程序退出中断的发送记为不确定，不计成功。
- Telegram FloodWait 阻止该账号继续发送；群慢速模式仅阻止该账号在对应群发送。显示倒计时，时间结束后仍需用户手动触发。
- SQLite 版本迁移保存配置、账号、短句、草稿、群置顶、发送状态与计数。消息标识去重，成功状态与数量在同一事务写入。

## 交互与数据

主窗口 `Ctrl+W` 与“程序 → 关闭窗口”复用 × 的关闭逻辑：有系统托盘时隐藏，无托盘时退出；对话框中不触发主窗口关闭，长按不重复执行。

连接设置统一通过“设置 → 连接设置”或 Ctrl+, 打开，第二行工具栏只保留添加/重新登录、重新连接和管理短句。首次真实启动未配置连接时仍自动打开设置窗口；保留 QObject 快捷键过滤器修复，避免遮挡左上角菜单。

系统托盘常驻：启动显示主窗口与托盘图标；× 保存草稿并隐藏，最小化仍留在任务栏。后台连续满 5 分钟断开所有账号并停止连接监测，保留会话与草稿。5 分钟内恢复取消断开，再次收起重新计时；最小化与隐藏互切不重置。截止时阻止新增发送，等待现有发送按原有 30 秒超时结束；取消未完成登录、连接及历史/群列表请求，退出登录或移除账号操作则等待完成再断开。托盘恢复当前聊天、草稿、引用及浏览位置，自动重连已登录账号并刷新最近消息；失败提示手动重试，不自动重发消息。设置窗口同步隐藏恢复；后台断开后的未完成登录关闭，需重新发起。仅切换其他应用不触发断开，无新增设置项。托盘“退出”与主窗口“程序 → 退出”执行真正清理，不退出 Telegram 登录；无托盘时 × 正常退出。首次隐藏提示操作方法；不增加开机启动、全局快捷键或新消息通知。

账号栏、群列表、聊天区、引用栏、输入框与右侧常驻短句面板组成主窗口。短句面板支持滚动及拖动分隔线调整宽度，悬停查看完整内容。群列表支持搜索、右键置顶；双击消息或右键引用。上翻暂停自动滚动，提示新消息并允许回到底部；当前聊天发送成功后自动回到底部，其他账号或群的发送结果不改变当前滚动位置。

消息采用左右气泡布局：当前账号发出的消息靠右，浅绿色背景；其他发言靠左，中性背景。姓名按 Telegram 发言人 ID 从本地固定 12 色调色板选择并加粗，缺失 ID 使用灰色；当前账号姓名显示“（我）”，姓名已为“我”则不重复标注。普通短消息压缩为两行：第一行合并姓名、灰色时间及发送状态，第二行显示正文与媒体类型占位。引用回复在正文前增加灰色“引用：昵称：原文”，不再只显示回复编号；无文字媒体使用类型占位，缺失原文显示“原消息不可用”。历史优先复用本页原文，页外同群原文按去重后的消息 ID 批量查询；实时引用读取原消息，不递归读取其引用，查询失败不丢弃正文。发送请求固定引用原文快照，发送中与成功回执均显示快照，不增加发送成功后的查询。缩小气泡内边距和消息间距，长正文、长引用或长姓名仍按可用宽度换行，不截断内容。气泡最大为行内可用宽度的 75%；不增加配色查询网络请求，不同步官方配色。

右键“复制消息文字”复制所点消息的原正文；选中消息后 Ctrl+C 复制选中消息，Ctrl/Shift 支持多选并按显示顺序以换行分隔。正文保留原换行及特殊字符，不附加姓名、时间或发送状态，无正文媒体复制类型占位；选中气泡显示蓝色边框。复制不修改草稿、引用及发送状态，未完成消息也可复制。

消息发送者使用 Telethon 完整显示名，合并 first_name 与 last_name，群组/频道保留完整 title；无显示名时回退 username 或“未知发送者”。新登录账号标签同样保存完整显示名。消息引用沿用完整姓名，不增加发送成功后的姓名网络查询。

`Alt+1…9` 选前九个账号；取消短句 `Ctrl+数字` 快捷键。点击短句在光标处插入，有选中文字时替换选中文字，保留其余草稿，焦点回到输入框且光标停在短句末尾。

短句管理支持每条一个可选缩写，手动填写英文字母、数字或下划线，统一小写匹配；空缩写仅通过点击插入。添加或编辑时拒绝重复或互为前缀的缩写，例如 `wz` 与 `wzd` 不能共存，保存整库时再次校验且失败不改原数据。所有账号共用前缀，默认 `;`，前缀中的英文 `;` 与中文 `；` 等价匹配，可改为一个或多个非空白符号。键入触发串最后一个字母、数字或下划线后，立即精确匹配并替换光标前的触发串，无需空格，保留前后文字和引用；一次撤销可恢复完整触发串。空格正常输入。无选区时才替换，忽略普通按键长按自动重复；粘贴、草稿加载及替换后的正文不触发自动替换。光标处于较长字母串内部时不替换。面板显示触发串和正文；旧库存在前缀冲突时保留数据与点击插入，暂停冲突缩写的自动替换并提示修改。

中文输入法候选状态下，将候选字母与光标前的触发前缀一起匹配，完整命中后重置输入法候选并立即替换，无需切英文或按空格。拼音字母间的空格、英文单引号仅在候选匹配时忽略；未匹配的拼音正常选词。输入法提交英文缩写也支持替换。选区、粘贴和草稿加载仍不触发展开，替换正文不递归匹配。

`Enter` 发送，`Shift+Enter` 换行。忽略发送和账号切换的长按自动重复；未展开的输入法组合期间不触发账号快捷键或发送；对话框中不触发账号快捷键。短句库版本 1 升至版本 2，增加可空缩写字段，保留旧正文与排序，旧短句需用户自行补填缩写。前缀保存在本地 settings 中，与短句一同保存。

手动提交后立即清空输入和对应引用，已提交请求仍固定原文本与引用；可继续按 Enter 或点击按钮提交下一条，无需等待上一条回执。未完成消息在对应聊天底部显示独立气泡、“发送中”和转圈标记，身份栏显示未完成条数；不能引用尚未取得 Telegram 消息 ID 的气泡。按请求 ID 替换成功气泡，忽略重复回执；成功回执不重载草稿，避免打断新输入或清除相同的下一句。失败或结果不确定时移除对应临时气泡，将原文本恢复到对应聊天草稿开头，与新文本以换行分隔；有新草稿或引用时保留其引用，否则恢复原引用。提示用户先核对再手动处理，不自动重发。短句插入不会发送或清除引用，发送中及限流等待时仍可编辑草稿。Telegram 等待期间拒绝新提交，保留草稿；已提交请求继续独立处理。临时气泡不进入历史缓存或成功计数，后台停止转圈动画，恢复窗口后同步未完成状态。

数据默认位于 `%LOCALAPPDATA%/TGChatClient/real`，模拟模式使用 `mock` 子目录。账号会话与相邻 `tg_bot` 分开；日志只记录本程序脱敏的操作和错误类别。模拟模式不读取真实配置。

账号右键菜单提供需确认的退出登录与移除账号。退出撤销本工具的 Telegram 会话并清理会话文件，保留账号记录、草稿、常用群和统计；重新启动不会自动恢复已退出账号。移除先退出，再清除该账号全部关联本地数据和缓存；不注销 Telegram 账号，不影响其他账号、连接设置或共享短句。退出失败保留本地记录并提示重试。发送、登录或账号管理期间阻止冲突操作；退出/移除前取消目标账号尚未完成的群列表和历史请求，避免清理后回写。模拟模式可验证退出与移除，全部移除后重启不再生成示例账号；模拟账号不提供真实登录。

媒体显示 `[图片]`、`[贴纸]`、`[视频]`、`[音频]`、`[文件]`，不下载、解码或缩放预览，保留附带文字与引用。旧版图片缓存不读取、不自动删除。

消息使用 QListView、增量消息模型和绘制委托，不创建逐消息控件。每个聊天缓存最近 500 条与历史浏览窗口最多 500 条，最多缓存 10 个聊天；按最近访问顺序淘汰非当前聊天。未访问且未缓存的群不积累消息，发送回执独立处理。历史窗口分页前插、超限裁去尾部，按消息 ID 和行内偏移保持位置；新消息只更新最近缓存与提示，回到底部切回最近窗口。

托盘隐藏或最小化时停止消息绘制、排版与普通界面刷新；后台前 5 分钟保持连接与回执处理，随后暂停连接。连接服务线程保留，恢复窗口自动重连；模拟服务遵守相同生命周期且不重置历史消息或已退出状态。失败草稿先持久化，恢复或退出不覆盖。计数使用单次批量查询快照，仅启动、切换、账号变更、发送成功及北京时间跨日刷新；普通消息不查询计数。前台限流倒计时按需启动，后台停止、恢复按截止时间计算。

## 分阶段任务与交接

依次推进 T01 工程基础、T02 Windows 打包验证、T03 模拟界面、T04 登录连接、T05 真实聊天、T06 持久化计数、T07 集成交付。每项独立验收，状态见 [TASKS.md](TASKS.md)。

现阶段 T02 受 Windows 构建环境限制，先编写构建流程并继续实现不依赖 Windows 的源码。不能将源码完成视作 Windows 验收通过。

每轮结束更新任务和 [HANDOFF.md](HANDOFF.md)，记录验证命令、环境、结果、下一步和阻塞项。后续会话先读取这三份文档，再核对源码，不重新推断已确认的产品决策。

## 验证与交付

使用 unittest/pytest、pytest-asyncio、pytest-qt、Ruff。模拟测试覆盖请求归属、草稿、引用、重复事件、跨日计数、限流、未知结果、快捷键、媒体占位、有界缓存与后台暂停。

Windows CI 使用 Python 3.12 执行检查和测试，再通过 PyInstaller 目录模式打包 zip。用户在无 Python 的 Windows 上验证解压启动、真实代理和登录、五账号切换、输入法、恢复连接及更新后数据保留。

真实测试凭据只在本地配置。CI 不登录 Telegram，不包含或上传私有数据。依赖锁文件必须由成功的 uv 解析生成；当前环境无法访问依赖下载域名，不手工伪造锁文件。
