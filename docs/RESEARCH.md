# Windows 多账号聊天工具：调研与需求记录

记录日期：2026-10-09。本文用于承接 `tg_bot` 项目中的讨论。

本文的技术结论来自相邻项目的代码与架构文档阅读，尚未进行 Windows 原型测试或外部技术选型验证。以下区分已确认需求、交互建议和待验证事项。

## 1. 使用场景与问题

用户主要在 Windows 上操作 5 个 Telegram 账号，每个账号每天目标发言 400 条，总计 2000 条。群里有发言上限，但目标条数与上限是否完全一致、有效发言的判定条件尚待确认。

常见内容是重复的短句，例如“我的好厚米”“你懂我意思”“我懂你意思”“我也是没招”。有实际信息的聊天较少，人多时刷屏很快，难以逐条阅读。

当前尝试过手动打字、快捷输入，以及双客户端快速切换，效率仍不理想。用户认为固定账号快捷切换有价值；逐条理解话题、生成多个候选再选择的流程不符合主要使用场景。

现有自动发言也未达到预期：语料模式经常重复别人说过的话，大模型接话生硬。此次方向转为用户主动操作的聊天工具，重点减少账号切换、输入和确认成本。

## 2. 已确认需求与第一版边界

用户已选择独立 Windows 应用，并要求在 `tg_bot` 上层目录建立新项目。

核心能力：

- 多账号登录与连接管理；快速切换当前操作账号。
- 查看聊天消息，选择目标群。
- 自定义快捷短句，快速发言。
- 自由输入、编辑和手动发送。

第一版不承担完整 Telegram 客户端的全部功能，也不以自动循环、定时发送或大模型生成为目标。消息发送由用户明确操作触发。

目前未确定桌面框架、快捷键键位、账号数量上限、媒体消息能力和安装包形式，不应将下文建议当成最终规格。

## 3. 交互建议（待确认）

建议采用账号栏、常用群列表、聊天区、底部输入框和短句面板的布局。

| 部分 | 建议行为 |
| --- | --- |
| 账号栏 | 常驻显示账号身份、连接状态和今日进度；支持固定快捷键与下一账号操作 |
| 群列表 | 常用群置顶，分别记住各账号上次打开的群 |
| 聊天区 | 实时消息、历史加载、引用回复；刷屏时允许暂停自动滚动 |
| 输入框 | 支持自由输入、粘贴、编辑；按账号与群分别保存草稿 |
| 短句面板 | 固定位置与键位；支持直接发送一条，或填入输入框修改后发送 |

切换账号仅切换操作对象，各账号连接保持可用。输入框附近持续突出当前账号与目标群，降低误发概率。

发送中、成功、失败应有明确反馈。快捷键需避免在其他应用或输入场景误触；发送期间切换账号时，已提交请求应绑定提交时的账号和群。一次手动触发只发送一条，避免按键长按、重复点击或不确定结果导致重复发送。

短句库、快捷键和进度规则都需要后续讨论。达到目标后的提醒或工具发送限制尚未定案。

## 4. 现有项目调研

参考项目位于相邻目录 `../tg_bot`（相对本项目根目录）。

现有自动发言实现包含定时发言、触发词回复和大模型接话，主要问题与内容适配及发送时机有关。新工具无需继承这些自动发言路径。

可参考的基础能力包括 Telethon 登录、多账号客户端管理、发送消息，以及通过群机器人回复校准发言数量。

现有 runtime 为每个账号管理一个可共享客户端，worker 和全局任务按生命周期借用连接；验证码与扫码登录使用临时客户端。该机制可以作为设计参考，但不应把新应用的生命周期直接绑定到 worker 启停。

**新应用使用独立登录会话与本地存储路径。** 不直接共用现有服务正在使用的 session 文件；是否提供迁移或导入功能尚未确定。

发送成功数量与群机器人认可数量应分开理解：本地发送确认不等于群内有效发言。现有项目的运行日配额计数主要保存在内存中，热加载保留、进程重启不自动从统计库恢复，因此计数逻辑也不能直接照搬。

## 5. 后续调研与决策

| 事项 | 要解决的问题 |
| --- | --- |
| 桌面技术与打包 | 比较 Windows UI、Telegram 连接层、事件通信、安装包和更新方式；框架尚未选择 |
| 登录与连接 | 验证多账号验证码、二步验证、扫码登录、重连和独立会话管理 |
| 消息同步 | 确认实时更新、历史分页、引用关系、群标识及账号切换后的消息归属 |
| 快捷键 | 明确账号选择、短句输入、直接发送、编辑模式和焦点规则 |
| 发送结果 | 验证提交中切换账号、断线、超时、失败与 Telegram 限流后的反馈，避免盲目重发 |
| 进度口径 | 确认群内有效计数、每日重置时区、跨群统计，以及 400 条目标与实际上限的关系 |
| 本地数据 | 确定会话、短句、草稿和统计的保存位置、访问保护、退出与删除行为 |

建议下一轮先确定操作流程：账号与群如何选择、短句键是否直接发送、草稿如何保留，以及数量如何核对。随后做 Windows 上的最小原型，验证切换速度与误发防护，再确定技术栈。

## 6. 原型验证方向

- 5 个账号保持连接，快速切换时身份、目标群、消息和草稿对应正确。
- 快捷短句和自由输入均可手动发送；一次触发对应一次发送。
- 发送中切换账号或群，不改变已提交消息的归属。
- 群刷屏时可暂停滚动；恢复后能查看新消息。
- 断线、登录失效、发送失败和限流都有可理解的状态，不静默重复发送。
- 本地发送成功数量与群认可数量分别展示，并明确来源。

验收细节随下一轮需求讨论补齐。本次仅建立文档，不连接 Telegram、不导入账号、不生成应用代码。
