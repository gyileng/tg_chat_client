# TG Chat Client

独立 Windows 多账号 Telegram 聊天工具，面向手动高频短句输入场景。

## 当前阶段

第一版源码、核心测试与 Windows 构建流程已建立。采用 Python 3.12、PySide6、Telethon 和 SQLite；界面实测、真实 Telegram 验收及 Windows 打包尚未完成。

后续会话先阅读 [开发计划](docs/DEVELOPMENT_PLAN.md)、[任务状态](docs/TASKS.md) 和 [会话交接](docs/HANDOFF.md)。原始 [调研与需求记录](docs/RESEARCH.md) 保留为背景资料，当前决定以开发计划为准。

## 开发与运行

```bash
rtk uv sync
rtk uv run python app.py --mock
rtk uv run python app.py
rtk uv run pytest -q
rtk uv run ruff check .
rtk uv run ruff format --check .
```

`--mock` 使用五个模拟账号，不连接 Telegram，数据与真实模式分开。真实模式首次填写 API ID、API Hash、代理，再添加账号。所有账号共用 SOCKS5/HTTP 代理；连接失败不切换直连。

真实模式可随时再次点击“连接设置”，或通过“设置 → 连接设置”、`Ctrl+,` 打开，修改代理端口等参数并保存，保存后重新连接全部账号；取消不改变配置。发送、登录或账号操作未完成时会明确提示先完成操作。模拟模式不使用连接设置，需退出后不带 `--mock` 启动真实模式。

启动和异常会写入本地日志，连接设置点击与窗口打开/关闭的临时诊断日志已移除。界面操作异常时会弹窗提示错误类型，脱敏错误位置保存在 `%LOCALAPPDATA%/TGChatClient/real/logs/client.log`（模拟模式为 `mock` 目录）。排查时提供按钮名称、错误类型和日志中的代码位置即可，无需提供 API Hash 或会话文件。

源码位于 `tg_chat_client/`，测试位于 `tests/`，打包配置与说明位于 `packaging/`。默认 Windows 私有数据路径为 `%LOCALAPPDATA%/TGChatClient/real`。开发可用 `--data-dir <目录>` 指定数据位置，仍分隔模拟/真实模式。

Windows 包通过 `.github/workflows/windows.yml` 在 Windows x64 环境构建。须解压并保留整个程序目录；无需安装 Python。当前尚未产出已验收的 Windows 包。

## 操作

- 点主窗口右上角 × 隐藏到右下角系统托盘，账号继续连接，已提交的发送继续处理；单击、双击托盘图标或右键“显示主窗口”恢复当前聊天和草稿。最小化仍留在底部任务栏。
- 完全退出：右键托盘图标 →“退出”，或主窗口“程序 → 退出”。退出保存草稿并断开连接，不退出 Telegram 登录；未完成发送仍按不确定结果处理，不自动重发。首次隐藏时会提示恢复与退出方法；系统托盘不可用时，× 正常退出。
- 右键账号可“退出登录”或“移除账号”，均需确认。退出保留账号、草稿和统计，再次使用需重新登录；移除先退出登录，再清除该账号的本地会话、草稿、常用群、缓存和发送统计，不注销 Telegram 账号，也不影响共享短句及其他账号。退出失败时保留数据并提示重试；发送或登录期间不可操作。
- `Alt+1…9` 切换前九个账号；短句不再使用 `Ctrl+数字` 快捷键。
- 点击短句在光标处插入草稿，有选中文字时替换选中文字，不直接发送；完整内容可通过悬停查看。右侧面板可拖动分隔线调整宽度。
- `Enter` 发送自由输入，`Shift+Enter` 换行；快捷键仅在主窗口前台生效。
- 每次手动提交后立即清空输入和引用，可连续输入并发送下一句，无需等待上一条回执；未完成消息各自显示“发送中”和转圈标记，身份栏显示当前聊天的未完成条数。成功回执替换对应气泡，不改新草稿；失败或结果不确定时将对应原文本恢复到该聊天草稿开头，保留新输入，不自动重发，先核对群消息再手动处理。Telegram 限流或群慢速模式仍显示等待秒数，结束后需手动发送。
- 消息按当前账号视角显示：自己发出的浅绿色气泡靠右，其他人的气泡靠左；姓名显示 Telegram 的完整名字与姓氏，按发言人 ID 固定配色并加粗。短消息采用两行紧凑布局，第一行显示姓名及灰色时间、回复编号和发送状态，第二行显示正文；长文本随窗口宽度自动换行。
- 右键消息 →“复制消息文字”，或选中消息后按 `Ctrl+C`，复制原正文，不带昵称、时间和发送状态；无正文的媒体复制类型占位。按住 `Ctrl` 或 `Shift` 可选择多条，按显示顺序以换行分隔复制；选中的气泡显示蓝色边框。
- 所有媒体仅显示 `[图片]`、`[贴纸]`、`[视频]`、`[音频]`、`[文件]` 占位，保留附带文字，可引用；不下载或显示预览。旧版图片缓存不再读取，也不自动删除。
- 双击消息或右键选择引用回复；短句也会使用当前引用对象。
- 管理短句窗口支持添加、编辑、删除、拖动排序，每条可设置一个缩写（英文字母、数字、下划线，大小写不区分），所有账号共用。添加或编辑时拦截重复及前缀冲突，例如 `wz` 与 `wzd` 不能共存。
- 默认输入完整的 `;nh` 或 `；nh` 立即替换为对应短句，无需空格，再按 Enter 手动发送。前缀可在“管理短句”自定义为一个或多个非空白符号。旧短句保留原内容，未设置缩写仍可点击；旧缩写若互为前缀，暂停这些缩写的自动替换并提示修改，点击仍可用。空格正常输入，粘贴和加载草稿不会自动替换。
- 中文输入法下，候选状态的字母组成完整触发串时也立即替换并结束该段候选，无需切换英文；未匹配的拼音正常选词。支持拼音字母之间的空格或英文单引号分隔；提交英文缩写同样可替换。
- 向上浏览暂停自动滚动；点击“回到底部”查看新消息。当前聊天发送成功后自动回到底部。
- 今日条数仅统计本工具发送成功的消息，按北京时间零点划分，不代表群内认可数量。
- 每个聊天保留最近 500 条及最多 500 条历史浏览消息，最多缓存 10 个最近访问的聊天。上翻时新消息不挤掉历史；可分页加载更早消息，点击“回到底部”返回最近消息。已淘汰聊天重新打开会加载最近消息，不影响草稿、引用和统计。
- 隐藏到托盘或最小化时暂停聊天绘制和周期计数查询，连接和收发仍继续；恢复时同步消息与发送状态。

## 已确定方向

- 一个窗口管理多个账号；账号保持连接，支持快速切换。
- 支持查看群消息、快捷短句，以及自由输入、编辑和手动发送。
- 每次发送由用户主动操作触发；自动循环、定时发送和大模型生成不属于当前第一版目标。
- 使用独立登录会话，与相邻的 `tg_bot` 服务分开管理。

## 性能验证

`scripts/benchmark.py` 使用临时数据、五个模拟账号，每账号累计接收 10,000 条文字消息，不连接 Telegram。运行 `rtk uv run python scripts/benchmark.py --output performance-after.json`，记录分阶段内存、前台/后台空闲 CPU、30 次账号切换的中位数与 P95。Windows CI 的构建产物附带 `performance-after.json` 和压缩包大小。

对照旧版时，在同一机器、相同 Python/Qt 环境，用同一个脚本增加 `--source-root <旧版源码目录> --output performance-before.json`。模拟启动指标包含 Qt 导入和主窗口初始化，不含解释器启动，也不等同于打包程序冷启动或真实五账号联网性能。Windows 上另需验证便携包冷启动、中文输入、历史分页和真实收发；本机 offscreen 数据只作参考。本轮同机结果见 [性能记录](docs/PERFORMANCE.md)。
